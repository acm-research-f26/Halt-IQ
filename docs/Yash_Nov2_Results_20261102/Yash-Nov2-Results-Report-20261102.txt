How the orchestration works

I integrated separate Strands SDK writer, reviewer and conditional challenger agents around the same pinned Qwen2.5-1.5B-Instruct model served on a Colab GPU. The writer proposes an answer and evidence; the reviewer returns actual feedback. A separate Hobson/Decider verifier supplies a score, with BGE used for evidence ranking. The Python orchestrator passes those signals to an eleven-feature linear policy. [2]

Policy action | Agent interaction

STOP | Return the current answer.

REVISE | Pass the current draft and reviewer feedback to the writer, then review and verify the revision.

INVOKE | Ask the challenger for an evidence-linked check; pass its actual response into writer revision, then review and verify.

These are separate role instances and feedback exchanges with shared model weights. Challenger interactions are recorded in action-branch training, the always-invoke control, and three retained seed-1 learned-policy paths. In the primary comparison, learned3 chose STOP on all ten completed paths and made no challenger call. [2, 3]

What I trained and integrated

I collected action branches from twenty training questions and used ten separate development questions for checkpoint selection. The targets maximize returned answer F1 minus 0.002 per additional role call. The classifier learns STOP, REVISE or INVOKE from public features such as verifier confidence, reviewer approval, draft position, answer changes and feedback cues. Gold answers are confined to external scoring. [2]

All five linear heads were fitted for 200 epochs with Adam (learning rate 0.03; L2 0.001), selected using development utility, and frozen before test execution. I also implemented matched three-draft/ten-role-call caps, failure-inclusive scoring, and physical request accounting. Vedanshi is credited for the verifier/reranker approach and Shree for the inherited linear stopping head. [2]

What the results explain

The inherited binary AND produced the same scores and calls as the verifier loop on this cohort. The new action policy instead preserved the first draft and avoided further revisions: 52 of 59 training-state targets favored STOP, and the primary learned paths followed that action. This routing pattern explains the lower call count and is consistent with avoiding answer degradation during later revision. [1, 2]

Evidence grounding was scored separately: learned3 supporting-fact F1 was 26.4 and joint F1 was 15.8; joint exact match was zero in every arm. The accompanying CSV includes all twelve answer, supporting-fact and joint metrics. [1]

The professor's paper on defeasible video entailment motivated an evidence-linked challenger that can test an existing answer. The implementation and HotpotQA results here are our adaptation; the paper summary is provided separately. [4]
