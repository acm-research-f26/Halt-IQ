Frozen methods

The pinned HotpotQA distractor validation plan contains 20 training, 10 development and 20 test questions. All fifty IDs are unique and excluded from 350 previously used or prepared IDs. Selection is seeded and stratified using public type, level and IDs. Gold labels are confined to external scoring; they never enter role prompts, features or the action mask. [3]

Action | Actual transition

STOP | Return the current draft; no further role call.

REVISE | Writer uses previous draft and reviewer feedback; then reviewer and team verifier assess the revision.

INVOKE | Challenger examines the public evidence; its actual response enters writer revision, then review and verification.

Matched paths allow at most three drafts, ten attempted role calls, and one INVOKE transition. A parser-level format correction is another measured call within that cap. Server/SDK failures propagate. A cap return is not gate approval. [3, 4]

Training obtains one initial state per question, then clones it to measure every legal one-step action and reachable depth-one branches. Utility is returned answer F1 minus 0.002 per additional attempted role call; failed branches retain zero answer F1 and their measured penalty. Physical shared-prefix calls are counted once. The classifier uses eleven public features and question-balanced masked cross-entropy. [3]

Five CPU linear heads use initialization seeds 0-4, Adam, 200 epochs, learning rate 0.03 and L2 0.001. Each keeps its earliest best development-utility epoch. All five freeze before test work; deployment head 0 is primary and head 1 is predeclared replication. This is one-step supervised action learning, not language-model fine-tuning. [3]

Features summarize verifier confidence, reviewer approval, draft position, answer change/repetition, feedback cues, challenger use and text lengths. Runtime uses Qwen2.5-1.5B-Instruct in FP16, with output caps of 512 writer tokens and 256 each for reviewer/challenger. Hobson v19 via Decider and BGE provide separate verification/evidence ranking. Shared LMFE 0.11.3 schema filtering and strict postvalidation apply to every arm. They do not ensure factual support or avoid truncation; numeric minimum bounds require postvalidation. [3, 4]
